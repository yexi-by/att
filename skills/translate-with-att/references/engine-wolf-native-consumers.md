# WOLF 条件对话、内部键与原生写回

适用于 WOLF RPG Editor 游戏通过外部解包、数据库／事件适配器接入 ATT Generic，
以及收到 NPC 漏翻、姓名残留、动态提示或数据库访问错误反馈后的返修。
WOLF 的原生提取、重建和运行语义由外部适配器负责；ATT 的输入、状态和验收仍遵循现行规格。

## 1. 条件字段与内嵌脚本覆盖

数据库字段的编辑器名称不能单独决定是否提取。有些自定义对话系统只把默认字段命名为
“对话”，却把同一记录中的其他脚本字段命名为角色状态、时段或条件；仅按字段名关键词
筛选会遗漏这些分支。反过来，备注和编辑器说明也可能包含自然语言，不能因此全部送译。

- 从实际对话事件追踪所读数据库类型、记录、字段和条件选择，建立显示来源清单；同时检查公共事件、地图事件及独立界面文字。
- 对已经确认存放脚本的字段，以当前项目的明确位置策略补充提取范围，遍历全部相关记录与条件字段。修改外部提取器时覆盖“无策略仍保持原筛选”“策略字段进入提取”“非显示备注仍排除”三类行为。
- 依据该游戏的实际脚本语法区分正文、说话人／表情头、分隔符、命令、空行和资源引用。头部中可能同时有显示名称和内部身份，分别确认其消费者后处理；不要把整个脚本单元格作为无结构正文翻译。
- 在外部映射中保存稳定来源位置及脚本结构；补提取沿用已有译文和状态，不用原版覆盖已经修订的输出。

按 [Generic 分组规则](../../../docs/generic/jsonl.md#3-从源格式建立-group-与文件范围)
将同一条件分支内的连续对白、旁白、问答和选项保留为完整语境；Unit 对应独立写回位置，
不要按显示行机械拆句，也不要把互斥分支拼成一段对话。源位置与重建数据留在外部映射，
不向 JSONL 添加私有字段。

## 2. 数据库错误与内部键

遇到数据库“名称不存在”“项目不存在”或负索引错误时，从错误所指的实际读写命令向上追踪：

1. 确认此次操作的数据库类别、类型、记录和字段参数，以及参数是固定数值还是运行时求值结果。
2. 查明名称转索引、字符串变量赋值和调用参数的来源；与同版本原版比较，定位最早发生变化的生产者。
3. 若内部名称被误译，恢复原键及其引用，再检查全部同类生产者和消费者。不要仅给负索引增加默认值，或新建一个译名字段来绕过错误。
4. 在原生读取结果上验证名称仍解析到正确字段，并覆盖受影响入口、参数分支和相关记录；除预期文字或键修复外，数值参数、事件顺序和控制流应保持原值。

数据库类型名、记录名、字段名、公共事件参数和字符串变量都可能参与名称查找。
某个值同时用于内部查找与画面显示时，保留逻辑原值，在已确认的最终显示边界使用精确映射；
不要对整个数据库或脚本做全局替换。反向转换也应核对这些键，防止旧译文再次覆盖修复。
类型编号、事件编号和字段范围依游戏而定，不复用其他项目的固定编号。

## 3. 姓名、动态提示与界面残留

正文已经翻译，画面仍可能从独立字段或运行时组合中取得名称。沿实际消费者分别核对：

| 反馈 | 需要追踪的来源与生命周期 |
| --- | --- |
| 正常对话或历史记录中的姓名残留 | 内嵌脚本的说话人头、字符串变量、姓名格式化事件，以及写入记录与绘制记录的各自入口 |
| 获得物品、技能、数值变化等提示残留 | 固定提示模板、运行时数据库名称、计数与单位的拼接；一起检查同类固定提示和动态提示 |
| 菜单、升级、回想或保存界面漏翻 | 自定义公共事件、数据库显示槽、图片文字，以及创建界面时复制到变量的值 |
| 切换界面后留下标签或遮挡 | 新增文字图片的编号、显示层与退出／返回时的清除路径；核对共享绘制事件的全部调用方 |

字符串映射应作用于实际绘制所用的显示值，保留查找、比较、保存和格式化参数的身份。
完整标签与复合标签共用映射时避免子串替换误伤，优先匹配完整已确认的显示值。
英文是否保留依任务要求决定，不能因为未译字符串含源语言字符就判断它一定属于可见正文。

反馈已经说明全新游戏、正常正文也有问题时，先检查这些当前入口，不能仅归因于旧存档或日志缓存。
修复覆盖整类来源与消费者，再安排新游戏、读档、历史记录和界面进入／返回的人工检查项。

## 4. 保护约束与译文修订

按 [Placeholder 规格](../../../docs/translation/placeholders.md)保护游戏实际使用的控制符与协议。
先区分语法换行、脚本分隔和视觉折行：Generic 允许 Unit 内 LF 数量变化，若原生脚本对正文
物理行数、空槽或分隔位置有额外要求，由外部适配器明确保护并验收，不能把它视为 ATT 默认契约。

- 多条规则先在完整源文范围检查是否重叠，以及 `scopes`／`ids` 是否命中当前项目；不要因准备失败而删除必要保护。
- 需要保留已有英文、数字或标记时，限定实际来源与匹配范围。过宽的规则可能把译文中新出现的普通字符误识别为新增技术身份。
- 修改保护规则后重新核对原文的全部保护片段、数量和顺序，确认没有漏掉原有控制符，再按当前契约复验已有译文。
- 修订 ATT 已管理条目的译文或恢复其中被误改的协议时，经 [Manual](../../../docs/manual/README.md) 或受管 [Lua](../../../docs/lua/README.md)写回 ATT 状态，再重新导出与 WriteBack。未纳入 ATT 的技术键由外部适配器从原版映射恢复，并更新提取保护策略；不要只改部署文件让状态与产物脱节。

纯符号或空白条目按实际显示用途记录保留理由。无假名残留只是一项筛查结果，不能证明共享汉字
文字已翻译、原意正确或所有条件分支都已覆盖。

## 5. 原生读回与交付边界

先在隔离材料中验证未修改内容的解析／重建往返，再用少量真实替换文字验证写回位置和消费者。
原生字符串长度变化会影响后续长度或偏移，使用匹配格式的 reader／writer，避免固定偏移覆盖。

最终封包或部署完成后，从实际输出重新读取，而不是仅检查重建前的 JSON：

- 逐位置核对当前译文与正文，比较脚本头、命令、空行、分隔符、资源引用和内部键；对全部同类条件字段建立覆盖清单。
- 核对数据库名称解析、事件参数及跳转等受影响语义，区分未翻译正文与有意保留的技术字符串。
- 检查实际字体对完整译文字符集的覆盖，以及本轮修改之外的文件、存档和个人设置保留情况。
- 独立补丁只含实际需要的资源与依赖；重新解包核对文件集合和内容，排除游戏存档、ATT 项目、日志和凭据。

按 [外部适配器验收](../../../docs/generic/adapter-verification.md)记录来源、最终读回正文、
消费者与布局证据。读回、名称解析模拟、字体字符覆盖和封包哈希各自只能证明对应检查通过；
画面排版、入口状态与游戏流程仍交由[人工实机验收](../../../docs/guides/acceptance.md#6-人工实机验证)，
不能把静态检查通过写成全流程已实测。
