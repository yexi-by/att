# WOLF 条件对话、内部键与原生写回

适用于 WOLF RPG Editor 游戏通过外部适配器将数据库（`DataBase` / `CDataBase` / `SysDataBase`）、公共事件（`CommonEvent.dat`）与地图事件（`.mps`）接入 ATT Generic，以及排查 NPC 分支漏翻、姓名残留或数据库查找报错的场景。

## 1. 条件对话字段与单元格内嵌脚本

- **从读取事件反推对话字段**：`.project` 中的编辑器字段名不能单独决定提取范围。自定义对话系统常把默认字段命名为“对话”，而将同记录下按角色状态、好感或时段拆分的脚本放在其他条件字段中；仅按字段名关键词筛选会漏掉分支，盲目全取又会混入非显示的开发备注。需顺着对话公共事件和地图事件的数据库读取指令，确认实际消费的类型、记录与字段范围。
- **拆解单元格内的脚本结构**：存放对话的数据库单元格常内嵌自定义脚本，混有说话人/表情头、控制命令、分隔符、资源名与台词正文。按该游戏的脚本语法解析单元格，仅将可见正文与选项槽映射为 Unit，并按 [Generic 分组规则](../../../docs/generic/jsonl.md#3-从源格式建立-group-与文件范围)将同一条件分支下的连续对话归入同一 Group（不按显示行切碎，也不把互斥分支拼成一段）。

## 2. 数据库名称查找与负索引错误

WOLF 数据库读写与公共事件支持按名称字符串（类型名、数据项名、字段名或字符串变量）解析索引；若参与查找的内部名称被当作显示文本翻译，运行时解析会失败并返回 `-1` 等负索引：

- 遇到数据库报“名称不存在”“项目不存在”或负索引访问错误时，从报错指令向上回溯数据库类别、类型、记录、字段参数的来源，对照原版定位最早被改动的名称生产者。
- 恢复被误译的内部查找键原值及其引用；当同一名称既用于内部查找又用于画面显示时，底层数据保持原值，在最终显示边界做“原名 → 译名”的精确映射。

## 3. 姓名、动态提示与界面文字图片

- **对话栏与历史记录姓名**：说话人名称可能来自内嵌脚本头、字符串变量或姓名格式化公共事件，且实时对话框与历史记录（Backlog）的写入、重绘常走不同入口，需分别追踪核对。
- **物品与数值动态提示**：获得物品、技能或属性变化的提示常由固定模板与运行时读取的数据库名称、数量、单位拼接而成。排查时同步覆盖固定模板与动态名称来源；共用显示映射表时优先匹配完整词条，防止子串替换误伤复合标签。
- **自定义界面与文字图片清除**：自定义菜单、升级、回想和存档界面常通过公共事件将文本渲染为图片（Picture）。若切换或退出界面后残留旧文字遮挡，检查对应文字图片的编号、图层以及各退出分支的清除路径。

## 4. 控制符保护与二进制写回

- **控制码与行数约束**：按 [Placeholder 规格](../../../docs/translation/placeholders.md)保护 `\cdb[...]`、`\cself[...]`、`\udb[...]`、`\v[...]`、`\f[...]`、颜色与停顿控制符。若自定义脚本解析器依赖固定的物理行数、空行或分隔符位置，提取与回填时保持原有行结构不变。
- **重算长度与最终读回**：`.dat`、`CommonEvent.dat`、`.mps` 与 `.wolf` 封包均带显式长度与结构索引，不能按固定偏移覆盖字符串。使用完整解析并重算长度的 reader/writer 写回后，从最终部署资源重新读回，按 [外部适配器验收](../../../docs/generic/adapter-verification.md)核对条件字段覆盖、名称解析与控制流。
