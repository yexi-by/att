# Unity / Naninovel 的显示消费者与漏翻返修

## 适用结构与证据范围

用于 Unity 游戏通过外部适配器接入 Generic，且正文与自定义界面来自不同资源，或资源已经
写入译文、标题和弹窗仍显示原文的情况。Naninovel 相关步骤只用于目标构建确实存在该框架
及相应消费者时；类名、注册机制、语言标识和可写字段以该游戏的程序集与资源为准。

真实材料验证了序列化文本回填、目标构建原生脚本与表达式解析、托管程序集中的静态初始化、
实际标题 getter，以及实际确认调用传入的消息。托管测试中未执行完整 Unity 场景和语言管理器，
部分平台调用与显示入口被替代，确认动作未执行。这些证据不证明画面、字体和交互已实机通过，
也不表示 ATT 已原生实现 Unity 提取、程序集补丁或资源封包。

## 从截图建立来源与消费者关系

- 同一游戏可能同时使用 Naninovel 脚本、TextAsset、MonoBehaviour 字段、UI Toolkit
  `VisualTreeAsset`、TMP、图片字和托管程序集字符串。按发生问题的文本对象反查来源，
  不把脚本翻译完成视为菜单、评论、商品标题和确认弹窗已覆盖。
- 对每类文字记录“资源或程序集字段 → 注册及赋值路径 → 实际显示调用 → 回填位置”。
  UI Toolkit 的序列化标签和属性表都可能保存文字；核对两处的读取关系，并继续检查
  `Label.text`、按钮赋值或模板展开是否在加载后覆盖初始值。
- 截图中的按钮不能直接认定为图片字。先确认它使用文本组件、字体还是烘焙纹理；真实图片字
  进入图像流程，动态标签进入文本消费者调查。设计样例也可能被运行时参数覆盖，只有证明
  覆盖关系后才能将其列为保留项。
- 语言管理器能够切换，不证明游戏设置界面提供语言选项。核对实际设置视图、启动初始化和
  存档加载的语言恢复路径；分别记录引擎语言与自定义界面的语言选择，不猜测二者使用同一标识。
- 扫描假名只能找到部分候选，不能证明纯汉字姓名、动态组合或其他来源已经覆盖。用户要求
  保留的语言按对应显示槽核对部署前后不变；内部键、类型名、资源地址及表达式标识继续保留。

## 资源已译但运行时仍为原文

### 托管字段与静态缓存

- 在 Mono 构建中，从实际 getter、弹窗调用和字符串组合方法追踪字段读取，再追踪静态
  初始化器、语言赋值及注册路径。资源中的字段名或已译文档只是候选来源，不能证明该类型
  已注册，或实例与静态字段会被语言管理器更新。
- Naninovel 的 managed-text 资源、类型缓存和字段赋值机制若参与该路径，核对目标类型确实
  被发现、资源地址确实被加载、字段类型受支持，以及赋值时机。框架能更新部分注册字段，
  不等于游戏所有自定义字符串都走同一机制。
- 检查 `.cctor` 是否先把原文字段复制到数组或字典。之后字段变成译文，先前缓存仍可能保存
  原文；缓存存在也不证明它用于当前画面，必须沿实际读取方法确认。按目标行为修正缓存的
  刷新关系或显示读取，使后续字段更新仍生效。
- 对同一字段类别核对全部已确认的显示读取，例如标题枚举分支、购买与播放提示、返回与退出
  确认。不能仅修截图中的一个常量；没有消费者证据的字段保留为待确认，不批量改写程序集
  的全部字符串。
- 静态汉化范围内确需修改托管消费者时，使用 ATT 已接受且与稳定来源相符的值，保留原有
  分支、无效输入回退、参数、回调及存档动作。重开程序集核对修改范围与此前修复；Mono
  的方法体处理不能直接套用于 IL2CPP。

### 能区分赋值与加载的验证

- 先给静态字段手动赋译文，再调用显示方法，只能证明该方法会读取已赋值字段。它不能证明
  游戏会自行执行赋值，也会掩盖缺失注册、赋值过晚或重新加载原文的问题。
- 托管测试应使用实际静态初始化器、getter 或确认调用，从原始字段状态开始验证返回值或
  最终传入消息与 ATT 输出一致；按已定位故障补充字段恢复原文、后续字段更新和无效输入
  的反例。测试条件由真实读取关系决定，不把所有 UI 固定为同一缓存模型。
- 截取确认消息时区分调用路径与确认动作。在隔离测试中保留文本来源及组合路径，只替代
  必要的平台或呈现入口，并记录替代范围；不要为验证文字触发购买、解锁或存档修改。
- 若完整场景、语言管理器或字体系统没有执行，明确把结果标为托管调用证据。实际收到消息
  不等于已经渲染；某个截图已显示译文也不等于同类界面全部实机通过。

## 脚本、姓名与 Generic 回填

- 外部映射保留容器、序列化对象、字段位置、源值指纹及实际消费者，Generic 输入只使用
  [JSONL 规格](../../../docs/generic/jsonl.md)定义的字段。ID 不依赖本轮数组排序；
  同文不同来源各自可追溯，由 ATT 负责去重，不让去重丢失回填位置。
- Naninovel 的作者标记、玩家姓名变量和表达式属于解析结构。区分默认显示姓名、存档中的
  自定义姓名、隐藏姓名，以及脚本中引用它们的变量或记录键；沿实际消费者修改默认显示值，
  不把变量名或用户已保存的姓名替换成固定译名。
- 保护命令、插值、富文本标签和表达式外壳。双引号、转义与多层括号依据目标构建的原生解析器
  验证，不能只凭正则或解析失败后的显示回退认定成功。重复标签、成对标签及允许移动范围按
  [Placeholder 规格](../../../docs/translation/placeholders.md)核对。
- 使用该构建的原生脚本或表达式解析器重读回填结果，并核对记录顺序、命令参数、姓名引用
  和无关内容；能够隔离求值时，再验证默认、自定义与隐藏姓名等实际分支。重解析通过仍不
  证明完整演出与存档加载效果。
- 反馈新增来源时沿现有 ATT 项目补提取，并复用仍适用的已接受译文。核对原有来源映射和
  译文未变化，再消费全部本轮输出；[Generic WriteBack](../../../docs/generic/write-back.md)
  成功只证明译后 JSONL 已发布，不证明游戏侧资源或显示方法已采用它。

## 有效资源、字体与交付验证

- loose 资源、共享资源和 Addressables bundle 中可能有同类对象。沿目录与 provider 的实际
  加载关系定位有效来源，记录需要修改的重复承载位置；同名、相同对象编号或某份资源中已有
  译文，不能证明它是实际使用的实例。
- 重新解析最终资源及容器，核对目标对象、非目标对象与外部引用。若修改 bundle 内容，检查
  目标构建的 catalog/provider 是否消费大小、校验值或其他加载元数据，按其实际语义同步并
  回读；不能仅修改资源文件后就宣称加载链一致，也不把一种 catalog 格式固化为 Unity 通则。
- 字体按实际消费者分别调查，TMP、UI Toolkit 和普通 UI 文本可能使用不同资产与样式覆盖。
  动态字体检查源字体和实际部署字符集，不能以初始 atlas 为空判断缺字；常规与粗体样式分别
  核对。TMP 具体字段与静态资源往返读取已有
  [TMP 字体经验](engine-unity-tmp-font-fallback.md)，不把该方案默认用于其他文字系统。
- 最终交付核对资源、程序集和字体是否包含所有本轮已确认修复，重读已部署消费者并保护
  存档及用户设置。ATT 已登记项目无剩余、静态扫描无候选或补丁文件校验通过，都不能替代
  对尚未定位来源和真实游戏画面的说明。

验收分别说明资源解析与回填证据、托管原生调用证据，以及人工画面确认。还未观察到的界面、
语言恢复、首次字体加载、裁切和动态组合继续列为实机检查项。
