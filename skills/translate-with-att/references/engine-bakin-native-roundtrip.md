# Bakin 原生资源往返与播放器消费者

## 适用结构与证据边界

适用于已经识别为 RPG Developer Bakin、需要将二进制目录或播放器界面交给 ATT Generic
处理的项目。引擎适配器承担容器读取、语义提取、来源映射、反向转换与资源回填；ATT 继续
拥有翻译状态、术语、去重规划和候选验收。本页不表示 ATT 已实现 Bakin 原生命令或通用 writer。

已用 Bakin 2.6.0.2 官方 Windows 样本核对标题赋值、启动器解包代码和原生菜单资源，并用
原生目录子块的读取、初始化与保存验证关联恢复对往返结果的影响。这些检查覆盖资源与调用
关系；标题、菜单和字体的实际渲染仍需实机观察。容器布局、版本、程序集和字段需在当前构建
重新核对，不把已用构建的偏移、资源编号、加密参数或修补脚本当作其他版本的格式契约。

## 识别资源包后，先验证原文往返

- 发现 `data.rbpack`、`BKNPAK` 容器或 `.rbr` 目录记录时，分别确认容器头、内嵌目录、
  资源表、载荷与运行库的读写关系。第三方工具能够导出字符串，不等于其 writer 能无损
  处理同一构建；先以未翻译材料验证 parser/writer 往返，再进入 Translate。
- 扫描 `ReadString` 可以帮助发现字符串位置，但也会取得路径、内部键、编辑器描述和
  缓存副本。按实际显示调用筛选对白、选项、数据库说明、布局菜单、地点名、系统词汇与
  标题；以原生对象字段和命令属性建立来源绑定，不能把全部字符串读取结果直接送模型。
- 原生对象的读取与关联初始化可能是两个步骤。在上述构建中，`commonEventListInfo.load`
  暂存子文件夹，`save` 则遍历已关联的文件夹树；存在子文件夹时，直接 `load → save` 会丢失
  这些信息。
  原生子块的最小往返验证在 `initialize(catalog)` 后恢复了原字节；完整 `GameSettings`
  应核对 `initCommonEventListInfo(catalog)` 所需的目录对象，再验证整体往返。接口见
  [CommonEventListInfo](https://rpgbakin.com/csreference/doc/en/class_yukar_1_1_common_1_1_rom_1_1_game_settings_1_1_common_event_list_info.html)。
  局部适配器无法恢复关联时，保留对应子块原始字节。
- 未改动记录重序列化出现差异时，定位到具体字段、子块或尾部，再判断哪些字节归 writer
  所有。`Map` 等记录若在 reader 返回后仍有未消费字节，先确认其所属层和含义，再确定保留
  与重建方式；不能假定所有构建都有同一种尾部，或直接拼接未经定位的数据。
- 只有证明差异完全位于已识别的范围、目标字段可正确重建且其余数据原样保留，才继续封包。
  未知尾部、子块长度或非目标字段仍发生变化时，保留恢复材料并暂停该次写回；不能把差异
  自动归为正常序列化。
- 重建目录或替换字体时，核对资源表的名称、顺序、长度、偏移和压缩语义，比较未修改目录
  成员与非目标资源载荷。容器整体哈希会变化；目录能解压或文件存在都不能替代这些检查。

## 建立 Generic 映射与控制码恢复

格式与分组边界以 [Generic JSONL](../../../docs/generic/jsonl.md) 和
[TaskBlock 规划](../../../docs/translation/task-planning.md) 为准，控制片段以
[Placeholder 规格](../../../docs/translation/placeholders.md) 为准。

- 外部映射保留源快照、记录身份、字段或命令属性、原值和唯一写回位置；JSONL 只携带当前
  契约允许的字段。用事件命令、相关记录或菜单的真实语境建立有序 Group，不按任意字节块、
  屏幕换行或全文去重结果切断语境。重提取与续跑保留未改变来源的身份和自然顺序。
- Generic 没有 Bakin 内建控制保护。按当前消费者确认颜色、变量引用、等待、转义及其他
  控制片段，再建立对应 kind 的 Placeholder 规则；不要把整个含文字的包装区保护掉，导致
  可见正文未进入语言判断和翻译。
- 同一条文字中的重复颜色码、相邻包装或保护跨度重叠使验收失败时，先定位源 binding 和
  规则冲突。需要外部拆装时，仅在能够确定恢复的控制边界提取自然文本片段，完整上下文仍
  放在同一 Group；映射保存控制序列、空片段和恢复位置。不能按字符拆分，也不能靠增加
  请求次数解决结构错误。若译文需跨控制槽重排而适配器无法正确表达，保留为 unresolved。
- 回填恢复原有控制序列与必要的源换行形式，再验证片段身份、重复次数、顺序和最终插值
  结构。内部查找键及资源引用保留。变量值同时用于显示与条件判断时，保留变量原值、赋值
  表达式和比较常量，在显示边界映射译文。[字符串变量属于可保存的系统状态](https://rpgbakin.com/csreference/doc/en/class_yukar_1_1_common_1_1_game_data_1_1_system_data.html)；
  同步翻译赋值和比较常量仍会与既有存档中的原值不匹配，多个原值译成同一文字也会改变
  相等判断。验证覆盖新游戏与既有存档读取后的显示和分支。
- ATT 的 accepted、remaining、rejected 与外部映射覆盖分别对账。数字、空白、控制码、
  非源语标记和未登记的可见来源分别说明，不能把 pending 全部认定为待办，也不能用已登记
  集合的完成状态证明整个游戏没有漏翻。

### 标签已译但动态数值为空

- 先区分静态标签、直接数字、格式符与变量插值。数值消失但冒号或百分号仍在时，检查该
  显示字段的完整控制序列及实际解析器，不能直接归因于字体。已核对构建中的命名变量
  `\$[key]` 由 `GameContentParser.Token.UpdateVariable` 传给
  `SystemData.GetStrVariable`；方括号内即使含源语言文字，也是查找键。
- 只匹配反斜杠后字母命令的保护规则会漏掉 `$` 等符号开头的控制码。按消费者保护完整
  引用，包括符号、括号和键；保留其大小写与内部字节。将真实源片段交给当前 Placeholder
  检查，核对 Generic kind、重复引用、相邻控制码及重叠跨度，避免一条过宽规则吞掉可见
  正文。未被规则识别的引用可以随正文被改写，accepted 本身不能证明引用安全。
- 沿原版字段、稳定来源映射和当前 ATT 候选逐项比较控制序列。旧候选的变量键已被改写时，
  从对应源 binding 恢复技术引用，保留 ATT 自然文本；先确认每个槽的归属唯一，再沿
  [Placeholder 复验](../../../docs/translation/placeholders.md#保存规则与复验)更新规则和
  修订候选。缺失、重复或无法唯一对应时保留待修状态，不从译文猜变量名或重译全部正文。
- 同一症状可能分布在 HUD、角色详情、其他布局节点与事件脚本文字。按同一解析器和命名
  引用形态核对等价来源，分别记录字段覆盖与封包后回读；不能只修截图中那个面板。
- 可以用可识别的测试值调用同构建解析器，区分旧引用与恢复后引用是否能取得值。这只证明
  该调用边界的键解析；不证明真实场景完成了赋值、既有存档保存了预期状态或数值已经显示。
  引用与原版相符而画面仍为空时，继续核对实际加载的补丁、赋值来源和当前场景或存档状态。

## 正文已译但窗口标题或工具栏仍是原文

先把游戏目录文字、播放器资源、图片字与说明文档分开定位；正文 WriteBack 不证明其他来源
已部署。用当前发行副本和实际启动链确认读取者，再沿现有 ATT 状态补提取。

### 窗口标题

- 窗口标题与游戏内标题是不同消费者。在已核对构建中，调用链是
  `Yukar.Player.Program.startApplication → GameSettings.name → SharpKmy.Entry.setWindowTitle`；
  `GameSettings.meta.title` 和 `meta.subTitle` 不能替代前者的提取。后续构建以真实赋值调用
  为准，把读取到的字段纳入映射，不因为名称像元数据就排除它。
- 两个字段原文完全相同且已有有效 ATT 译文时，可以沿稳定来源复用已有候选，通过 ATT
  的受管导入与验收写入新增条目。核对来源快照、原文、候选状态和控制约束，不根据相似
  文本猜配，也不重新翻译已经确认的全部正文。
- 仅修标题时，验证目标记录和字符串位置，保留同一记录内的其他数据。封包后用原生读取器
  确认窗口字段等于 ATT 输出，比较非目标字段。播放器在启动时设置标题，重启后才验证
  实际标题；静态字段正确不能写成标题画面已经验收。

### 播放器原生菜单

- 调查实际加载的播放器与原生运行库。菜单可以位于 `kmyCore.dll` 或
  `kmyWindowsCommon.dll` 的 Windows `RT_MENU` 资源；存在 .NET 语言卫星程序集，并不
  证明当前工具栏从它们读取。按资源与加载调用确定来源，不只搜索托管字符串。
- 每个实际可用语言资源分别解析菜单层级、项目标题、命令 ID、标志和快捷键。不同语言
  资源的形状或命令编号可以不同，不能按数组位置互相覆盖；保留各自基线，只把显示值交
  ATT。正确处理助记符 `&`、字面量 `&&` 和制表符后的快捷键，避免移除助记符时同时丢掉
  英文单词的首字母。
- 在隔离副本中修改菜单资源后，重读模板并对账菜单结构与 ATT 输出，比较非菜单资源及
  代码段。资源重建可能移动容器位置，检查内容而不是只比较绝对偏移；若构建有签名或加载
  约束，验证修改后的文件仍满足实际加载要求，不能以关闭校验作为修复。
- 上述构建的启动器以 ZIP 读取 `bakinplayer.pak`，并以覆盖方式解出播放器 EXE；只修改
  旁边的 loose EXE 会在该路径执行时失效。其他构建先确认容器格式及真正的写入与加载者，
  再由对应 writer 更新有效资源，并验证重新启动后的载入结果。菜单资源补译不自动覆盖
  系统对话框、动态生成项或图片文字。

## 中文缺字时定位内嵌字体

- 对布局与对白分别核对字体绑定。已核对构建区分 `defaultLayoutFont` 与
  `defaultMessageFont`；布局项的显式 `font` 还可能覆盖默认值。用户只要求换界面字体时，
  定位实际 Font 记录和包内载荷，保留对白字体及无关消费者，不把所有默认字体一起替换。
- 先核对当前原生 Font 记录的字体类型、路径、字号、加载方式与共享资源引用。若多个记录
  读取同一个包内字体载荷，在已确认的资源位置替换字体；不凭文件后缀替换成引擎不支持的
  格式，也不把字号和其他记录参数一起改掉。
- 按最终部署字符串恢复控制码后的可见字符集合检查字形，包含中文、标点与特殊符号。
  系统字体、包内字体和 Windows 菜单字体的消费者分别确认，某一种字库覆盖不能证明所有
  界面都采用它。需要衍生字体时保留许可并遵守其命名条件。
- 保存后解析字体与资源引用，原生回读记录并比较非字体载荷。静态覆盖只能证明字符映射
  存在；标题、正文、菜单、长文本换行和裁切仍需在各自场景观察。

### 字形齐全但文字模糊、换行或贴框

- 字形覆盖、变量取值与布局渲染分别检查。确认有效字体后，对照目标项及父容器的字号、
  缩放、位置、尺寸、对齐、内边距、换行、裁切与阴影；不要把字符均有 glyph 等同于
  小字号可读，也不把名为 `scale` 或 `textScale` 的字段直接当作同一种字号设置。
- 标签与数值可能是独立子项。长标签换行时，先结合当前字库的字宽、容器空间和数值位置
  判断需要文字修订、字号调整还是尺寸调整；关闭换行不能保证文字没有裁切。仅文字已
  单行但贴边时，比较横向位置、对齐和留白，加宽并非自动成立的修复。
- 尊重本次修改范围。只改文字时保留位置、尺寸与换行字段；只调边距时保留文字、字库、
  字号和邻近数值位置。采用项目中已确认的字段和值，不把某次的宽度、缩放或位移固化为
  所有 Bakin 项目的默认参数。字体度量可以帮助选择候选，实际边缘与缩放结果仍看画面。
- 原生布局包含嵌套值类型时，反射修改 boxed `Vector2` 副本未必写回拥有它的对象。
  使用适配器的真实赋值路径，必要时逐层把修改后的值写回父字段；保存后重新加载目标
  字段，而不是只查看内存副本。对照上一轮有效布局，确认只有授权的字段变化，再按前述
  原文往返门禁核对包内非目标记录与资源。

## 验收与小范围返修

封包后重开实际候选包并重读目录，用同构建原生读取器对账目标字段与 ATT 输出。显示名称
可能存在重新加载后同步的别名；只有实际关联关系能解释的变化才纳入预期，不能放宽成
“所有 name 字段都允许改变”。恢复材料保留原件和上一轮有效译本，部署前确认发行文件
没有被其他改动替换，也不在仍运行的游戏中改写它正在使用的资源包。

分别交付 ATT 状态、来源覆盖、引擎回填、非目标资源保留、字体检查和实机观察结果。零
remaining、无源语言残留、原生回读通过或启动进程退出均不能证明全游戏渲染与行为正常。
菜单截图只支持截图里的标签，窗口标题在重新启动前保留为未实测。用户停止窗口操作后，
保留现有结果并停止该测试；只要求维护经验时，不重启翻译、游戏或封包。

反馈返修还应分别说明控制引用已恢复、解析器测试值可读取、目标布局字段已部署与人工画面
确认的范围。声明某面板已纳入引用修复，不等于该面板的真实数值与字体显示已经验收；后续
截图仍出现问题时，先确认截图使用的包与场景，再继续定位消费者。
